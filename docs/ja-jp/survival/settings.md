# 基本設定

## サーバー基本情報
- **サーバーアドレス**：`Play.RSerene.com`（RSerene の他のサーバーからコマンド `/server Survival` を実行して参加することもできます）。
- **サーバーコア**：[Lophine](https://GitHub.com/LophineLabs/Lophine)。
- **クライアント対応**：1.8 ~ 26.3 のクライアントに同時対応。
- **推奨クライアントバージョン**：26.3
- **人数と難易度**：最大同時接続数は 40、ゲーム難易度はハード。
- **視距離設定**：視界距離 16、シミュレーション距離 12。
- **睡眠システム**：プレイヤーの 30% がベッドに入ると夜の加速が始まります。オリジナルプラグイン [NoPhantomSleep](https://GitHub.com/Rain-Serenity/NoPhantomSleep) により、夜にベッドを右クリックするだけで一晩を越したと判定され、ファントムも湧きません。
- **死亡時のアイテム保持**：サーバーでは死亡時のインベントリ保持が有効です。

## 世界とサバイバルシステム

### 1. テレポートと家
- **コマンド**：`/back`（前回の位置）、`/dback`（死亡地点）、`/home`、`/homes`、`/sethome`、`/removehome`、`/spawn`、`/tpa`、`/tpahere`、`/rtp`。
- **数値の制限**：家は最大 8 件まで設定可能。`/tpa` の申請は 60 秒間有効。`/rtp` のクールダウンは 10 分で、着地点はオーバーワールドの半径 3200 ~ 32000 ブロックの範囲内です。
- **無敵時間**：テレポート後は 5 秒間無敵ですが、ブロックを壊したりブロックに触れたりすると早期終了します。

### 2. 領地
| 項目                | 数値              |

| 領地数の上限            | 8 ブロック          |
| 1 ブロックあたりの最大サイズ   | 512 × 512 × 256 |
| 高さの範囲             | -64 ~ 320       |
| 領地間の距離            | 最低 8 ブロック       |
| 範囲選択ツール / 情報確認ツール | 木のクワ / 糸        |
| 1 マスあたりの価格        | 0.05 ゲームコイン     |

- **権限とセキュリティ**：領地内では初期状態で PVP ができませんが、**爆発は初期状態で許可**されています。領地主は権限を個別に切り替えられます。
- **信頼の仕組み**：`/res padd` で他人に建築・破壊・コンテナ・インタラクトの権限を与えられますが、PVP を許可したり火をつけさせたりすること**はできません**。完全に信頼するには `/res pset &lt;ID&gt; admin true` を使います。
- **無効な機能**：飛行、ジャンプ高度、経験値／アイテムの保持、バックアップ、時間と天候、回復、領地チャット（領地の admin 権限を持っていても有効化できません）。
- **取引ルール**：領地の貸出・売買は無効で、領地を削除してもコインは返金されません。

### 3. 経済システム
- **通貨**：記号は `￥`、新規プレイヤーの初期残高は 100、上限なし、小数も使えます。

- **グローバルマーケット**：`/gmp market gui` でグローバルマーケットを開きます（その他のコマンドは「コマンド一覧」を参照）。税金は 5% です。

### 4. チャットシステム
- **基本の制限**：シングルチャンネルのチャットで、発言クールダウンは 2 秒、1 メッセージの最大文字数は 100 字。
- **クイック表示**：`[inv]`、`[ender]`、`[item]` を入力すると、インベントリ・エンダーチェスト・手持ちアイテムをそのまま表示できます。
- **ミュート中の制限**：ミュート中は `/me`、`/tell`、`/msg` などのコマンドが一切使えません。

## スロットリング設定

### 1. tick ごとの処理回数（limit）
- **意味**：単一の Folia 領域内で、そのエンティティが 1 tick あたりに最大何回処理されるか。
- **発動条件**：領域内のエンティティ数が limit を超えるとスロットリングが始まります。
- **効果**：1 tick あたり limit 個のエンティティの tick のみが処理され、残りのエンティティの tick はスキップされます。
- **例**：limit = 100、領域内に実際に 300 体いる場合 → 1 tick あたり 100 体のみ処理されるため、各エンティティは平均して 3 tick に 1 回しか処理されません。

### 2. 最大存在数（removal）
- **意味**：単一の Folia 領域内で、そのエンティティが存在できる上限。
- **発動条件**：領域内のエンティティ数が removal を超えると除去が始まります。
- **効果**：コアは最も早く生成されたエンティティから順に削除し、数が removal を下回るまで続けます。
- **目的**：エンティティが無限に溜まるのを防ぎ、領域のメモリや計算量の爆発を避けるため。
